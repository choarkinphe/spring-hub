# SpringHub

**自托管的 HandBrake / FFmpeg 视频转码工作台。**

SpringHub 把真实的 **HandBrakeCLI / FFmpeg**、持久化任务队列、存储浏览和结构化编码设置整合到中文 Web 界面中，适合家庭 NAS、个人媒体库和可信管理员的单机转换任务。

**正式发布和实际运行环境是 Docker 容器。WSL Ubuntu 仅用于源码开发、调试和回归测试，不是用户部署的前置条件。** 宿主机需要 Docker Engine 和 Docker Compose，不需要单独安装 Python、Node.js 或 HandBrakeCLI；这些运行组件由镜像提供。

后端使用 Python 标准库，前端使用原生 HTML / CSS / JavaScript，无需 npm 依赖或前端构建。黑、白、橙的界面统一呈现系统状态、任务进度和操作结果；它不是远程桌面，也不依赖 noVNC。

> **SpringHub 是转码工作台，不是媒体播放器或流媒体服务器。** 媒体由运行服务的主机读取与处理，浏览器只提交存储位置、相对路径和编码设置。

## 功能介绍

### 系统概览与编解码器检测

首页展示 CPU 使用率、内存用量、可见 GPU 数量、可用存储容量和 HandBrake 版本。型号、驱动、存储路径、采样说明及完整编解码器报告放在系统详情中，避免首页堆积诊断信息。

- 未知指标保持“未知”，不拿 `0` 冒充检测结果。
- 同一文件系统的容量合并展示，不重复相加。
- 正式部署的指标代表**容器可见环境**，不等同于完整宿主机监控；WSL 调试时则代表 WSL 环境。
- 编码器区分“引擎提供”“当前硬件不可用”“当前构建不包含”和“检测未知”。
- 视频编码器通过微型实例化任务检测，不单凭 `--help` 中出现名称或检测到驱动就判断可用。
- 缺失编码器提供获取指引与可复制命令；本机 FFmpeg 缺失时，可在“设置 → FFmpeg 与远程”明确确认后安装固定校验版本到应用数据目录，不安装系统包或驱动。

### 七标签编码设置

创建任务时打开编码工作台，按需调整参数，而不是把所有设置常驻在首页。

| 标签 | 主要功能 |
| --- | --- |
| 摘要 | 任务模板、HandBrake 预设、输出容器、输出位置与文件名 |
| 尺寸 | 宽高、自动或自定义裁剪、像素宽高比、尺寸对齐 |
| 滤镜 | 去隔行、降噪、电影帧率还原、旋转、灰度、翻转与锐化 |
| 视频 | 软件 / 硬件编码器、质量或码率、编码速度、调优、档次、级别、帧率与两遍编码 |
| 音频 | 多音轨、源音轨选择、编码器、混音、码率、直通或不输出 |
| 字幕 | 源字幕处理、外挂 SRT、烧录、默认字幕与强制字幕 |
| 章节 | 保留、移除或从 CSV 标记文件创建章节 |

这些控件映射到**有边界的结构化参数协议**，不是 HandBrake 所有命令行参数的完整镜像。不支持的字段和组合会明确拒绝，不会接受后静默忽略。

支持 MP4、MKV、WebM 等输出容器；具体编码器、音轨和容器组合仍受当前 HandBrake 构建及素材限制。

### 预设与任务模板

预设和模板解决不同问题：

- **HandBrake 预设**：使用引擎官方预设或已导入预设。官方预设提供中文显示与搜索，同时保留原始名称和说明。
- **任务模板**：保存常用的编码设置，支持新建、编辑、复制、删除、设为默认和 JSON 导入 / 导出。
- 模板导出可包含所需预设依赖；导入生成新身份，不覆盖已有模板。
- 模板不保存源文件和输出位置，不携带访问令牌或宿主机凭据。
- 选择预设后，未修改的控件不会把界面默认值强行覆盖到预设上。
- 创建任务时保存独立的预设与执行快照，修改或删除模板、原预设文件不会改变已创建任务。

### 播放模板、FFmpeg / rffmpeg 与外部调用

预装 **10 类 MP4 模板**：原有网站标准/轻量、食品与商品细节、手机兼容/省流量、平板、电视、现代 HEVC 和静音背景，新增 **HEVC MP4 · 保持源参数**。原 9 类为固定播放参数、常见 AAC；新模板仅 FFmpeg/rffmpeg，保持源尺寸、帧率与 8/10-bit 4:2:0，读取源视频平均码率为目标，复制兼容音轨/字幕并保留章节。重编码后的实际码率、文件大小和画质不保证相同；缺失可靠视频码率、HDR 或不兼容流会明确拒绝。内置模板只读，可复制、导出、设默认；HEVC 需设备支持。

保留 HandBrake，新增本机 **FFmpeg + ffprobe**，以及管理员预装的 **rffmpeg FFmpeg/ffprobe 兼容 wrapper**。任务明确选择引擎，不自动回退；请求仍为结构化参数，不接受 raw argv。HTTP API 支持按模板 UUID 提交；命令行客户端可提交、校验、查询进度/日志、控制任务和等待结果，使用同一服务队列。

远程采用相同绝对路径的共享存储，不由网页管理 SSH 或密钥。运行态暂停不支持；取消/超时不代表远端进程已退出，未确认的隔离产物保留给管理员处理。无真实节点时不宣称远程验收。模板参数、配置、API/CLI 示例和限制见 [播放与外部调用文档](PLAYBACK.md)。

### 参数预校验

无需选择源文件即可检查参数结构、预设解析及命令行映射，查看本次提交的参数和生成的命令行参数数组。

**预校验通过不等于一定能转码。** 此阶段不检查媒体文件存在性、源轨道、硬件准入或实际编码；提交和执行阶段仍会复验。

### 持久化队列与任务控制

任务和日志保存在 SQLite 中，刷新浏览器不会丢失队列。

- 查看任务状态、进度、速度、剩余时间、错误、输出路径和原始日志。
- 启动待执行任务，或重试失败 / 已取消 / 已中断的任务。
- 暂停和继续：正在编码的任务保留同一进程、临时产物和执行名额。
- 取消任务：停止执行，未通过校验的临时产物不发布。
- 删除任务记录与日志：**不删除源文件或输出媒体**。
- 筛选、搜索、勾选与批量启动 / 继续、暂停、取消和删除记录。

队列分类、搜索和批量操作作用于最近 **100** 条任务列表；首页状态统计来自全库。服务重启后，在途任务标记为中断，不伪装成可从原进程继续。

### 七类设置

| 分类 | 可配置或管理的内容 |
| --- | --- |
| 常规与界面 | 刷新频率、默认队列分类、标准 / 紧凑列表密度 |
| 输出与文件 | 默认可写位置、命名模板、命名预览、同名拒绝或自动编号 |
| 转换与队列 | 1–8 个并发任务、新任务自动启动、编码超时 |
| rffmpeg 远程 | FFmpeg/ffprobe 兼容入口、共享探测目录、主动检查已保存配置 |
| 编码默认值与模板 | 默认模板、模板管理与导入 / 导出 |
| 完成通知 | 成功 / 失败页面提醒、可选提示音和浏览器系统通知 |
| 存储与维护 | 存储位置状态、历史任务记录与日志的清理预览和确认 |

服务设置保存在数据库中，界面与通知偏好仅保存在当前浏览器。并发调整立即影响新任务领取，降低并发不会终止在途任务；新任务的超时和同名策略在创建时冻结。

同名自动编号使用 `文件名 (1).扩展名` 等形式，由后端分配并在发布时检查，**不自动覆盖原文件**。命名模板支持 `{source}`、`{encoder}`、`{preset}` 和 `{ext}`。

设置支持未保存确认、分类恢复默认草稿和并发修改冲突检查。历史清理需先预览，再确认，只清理符合时间 / 状态条件、已经结束且释放执行的记录与日志。

完成提醒基于独立任务事件，不依赖最近 100 条列表。声音受浏览器自动播放策略限制，系统通知需主动授权；**关闭页面后不提供后台推送**。

## 使用流程

1. 使用 Docker 部署服务，将媒体和输出目录挂载到容器，并在页面确认容器内的 HandBrakeCLI 可用。
2. 打开工作台，检查系统概览和存储状态。
3. 点击“创建任务”，从已配置的存储位置选择源文件。
4. 选择预设或模板，调整输出容器、文件名及编码参数。
5. 可先“扫描源文件”或“预校验参数”，然后“加入队列”。
6. 在任务列表查看进度，点击任务打开详情；必要时暂停、继续或取消。
7. 转码完成并通过输出扫描校验后，产物才发布到最终位置。

## Docker 部署与快速开始

Docker 是本项目的正式发布与运行方式。当前仓库提供 [Dockerfile](Dockerfile.handbrake) 和 [Compose 配置](compose.handbrake.yaml)，快速开始采用**从源码构建镜像**的方式，不假设已有发布到镜像仓库的成品镜像。

### 宿主机要求

- Docker Engine 和 Docker Compose v2，可运行 Linux 容器。
- 可供容器访问的媒体目录，以及用于 SQLite 的本地持久化存储。
- 目录权限允许容器用户 **UID/GID 10001** 读取媒体、写入输出。
- 使用硬件编码时，宿主机另需配置匹配驱动和容器设备透传；镜像内的 HandBrake 也必须包含对应编码器。

用户部署不需要 WSL、Python、Node.js 或宿主机 HandBrakeCLI。它们只在源码调试章节中出现。

### 获取项目并配置媒体目录

```bash
git clone https://github.com/choarkinphe/spring-hub.git
```

```bash
cd spring-hub
```

复制[环境变量示例](.env.handbrake.example)：

```bash
cp .env.handbrake.example .env
```

编辑 `.env`，将 `SPRINGHUB_MEDIA` 指向宿主机的真实媒体目录，例如：

```dotenv
SPRINGHUB_MEDIA=/srv/media
```

默认 Compose 将该目录挂载为容器 `/media`，默认输出位于其 `converted/` 子目录。首次生成的配置要求 `.cute-cat-mounted` 标记；确认媒体目录或 NAS 已正确挂载后，在其根目录创建标记，例如：

```bash
touch /srv/media/.cute-cat-mounted
```

**不要在 NAS 未挂载时创建目录或标记。** 先确认真实挂载点和 UID/GID 10001 的读写权限，避免转码写到宿主机底层空目录。

### 构建并启动

```bash
docker compose -f compose.handbrake.yaml up -d --build
```

打开 **http://127.0.0.1:8080**。默认只绑定宿主机回环地址；远程访问需显式配置 API token，并通过 TLS 反向代理提供服务。

```bash
docker compose -f compose.handbrake.yaml ps
```

```bash
docker compose -f compose.handbrake.yaml logs --tail=100 springhub
```

### 配置与持久化

| 容器位置 | 用途 |
| --- | --- |
| `/media` | 宿主机媒体目录的挂载点；默认包含输出子目录 `converted/` |
| `/data/config.toml` | 首次启动生成的服务配置；也可通过只读挂载提供自己的配置 |
| `/data/cute-cat.db` | 任务、日志、设置、模板等 SQLite 数据，必须放本地持久化存储 |
| `/tmp` | 容器临时空间，默认使用 tmpfs |

`/data` 使用 Compose 命名数据卷 `cute-cat-data`，保留该历史名称是为了兼容已有数据。不要使用 `docker compose down -v` 删除持久化数据，也不要让两个服务实例同时管理同一数据库。

如需独立输出目录或多个存储位置，使用[配置示例](config.example.handbrake.toml)，在 Compose 中添加相应 bind mount，并将配置挂载到 `/data/config.toml`。配置中的路径必须是**容器内路径**，不是宿主机路径。

部署配置采用非 root 用户、只读根文件系统、丢弃所有 capability；应用不会挂载网络共享、安装驱动或接入 Docker socket。

> **运行定位与验证状态分开说明：** Docker 是正式运行环境，但目前实际通过的调试和回归在 WSL 中完成，Docker 镜像构建、启动和真实容器转码尚未在当前环境验收。WSL 测试通过不能当作 Docker 已验证；正式使用前需检查容器状态、HTTP 接口、引擎版本、目录权限，并完成真实样例任务。

## NAS 与存储配置

### SMB / NFS

网络共享由宿主机或 Docker 挂载，然后作为已配置的存储位置使用；Web 应用本身不执行挂载。

- 宿主机挂载后，可将 `/srv/nas/video` 等目录映射到容器 `/media`。
- Compose 文件中包含可选 NFS / CIFS volume 示例。
- 可配置 `mount_marker`，标记缺失时拒绝访问，避免共享未挂载时把本地空目录误当作 NAS。
- SMB 凭据保存在宿主机私密凭据文件中，不写入源码、镜像、日志或前端。
- SQLite 数据库和输出锁必须位于**本地文件系统**，不要放在 SMB / NFS 上。
- 输出发布使用同文件系统硬链接以实现不覆盖；目标共享是否支持该行为，需要在实际部署环境验证。不支持时安全失败，不降级为覆盖已有文件。

## 安全与数据保护

SpringHub 面向可信管理员的单机自托管，不是多租户公网平台。

- **参数白名单**：客户端不能提交任意 FFmpeg / HandBrake 命令或 shell 参数；结构化参数校验后转换为 argv，执行时不经过 shell。
- **存储边界**：客户端只提交存储位置 ID 和相对路径；拒绝绝对路径、`..`、盘符及逃逸到根外的软链接。
- **源文件保护**：拒绝输入与输出相同，包括硬链接 / 软链接别名。
- **安全发布**：任务先写隔离 staging，检查非空并扫描到正时长后才发布；失败和取消不删除已有输出。
- **记录与媒体分离**：删除记录、清理历史、删除模板不会删除媒体。
- **无系统特权**：不安装系统包或驱动，不接入 Docker socket，不授予挂载能力，不提供关机或删除源文件操作。FFmpeg 一键安装仅写应用数据目录，使用固定 HTTPS 下载与 SHA-256 校验，须主动确认。
- **访问控制**：对外提供服务时使用 `SPRINGHUB_API_TOKEN`，并在 TLS 反向代理后部署。Compose 的 token 环境项需按文件注释显式启用，仅写入 `.env` 并不会自动传入容器。

输出校验不是逐帧完整性或画质验证；路径检查也不是防御恶意宿主机管理员持续替换目录的完整方案。完整边界见[安全与验证记录](CONVERGENCE.md)。

## 开发与测试

### WSL 开发调试，不是正式部署

开发环境为 **WSL Ubuntu**，需要 Python 3.11+、真实 HandBrakeCLI；Node.js 仅用于前端回归。宿主机直接运行 Python 服务和预览脚本只是开发调试路径，发布后仍在 Docker 容器中运行。

安装开发用引擎：

```bash
sudo apt-get install -y handbrake-cli
```

先执行下方回归测试，再启动独立调试预览：

```bash
SPRINGHUB_HB_PORT=18087 bash next/preview.sh
```

调试页面为 **http://localhost:18087**，Claude Code 配置名为 `springhub-preview`。调试数据默认位于用户缓存目录，可用 `SPRINGHUB_HB_STATE` 指定。

> 预览优先使用真实 HandBrakeCLI；缺失时明确回退到接口 mock。Mock 不执行真实转码，生成的 `movie.mp4` 是占位文件，不是有效媒体。真实调试任务需使用实际媒体文件。

可选的[真实 CLI 验证工具](next/tools/verify_cli_mapping.py)会生成隔离素材并运行 CPU 编码，请在已安装真实 HandBrakeCLI 的环境中按[详细文档](README.handbrake.md)执行。

## 改名与历史数据兼容

项目从 Cute Cat 更名为 **SpringHub**，公开入口推荐使用 `python -m springhub` 和 `SPRINGHUB_*` 环境变量。

- `python -m cutecat` 与旧 `CUTE_CAT_*` 环境变量仍兼容，显式新变量优先。
- `cute-cat.db`、`cute-cat-data`、`.cute-cat-mounted`、浏览器偏好键及模板 JSON 格式保留历史标识，避免改名后数据或偏好失效。
- Compose 服务现在名为 `springhub`。升级时先停止旧实例，保留 Compose 项目名与数据卷，**不要使用 `down -v`**。
- 已删除的旧 Rust / FFmpeg 实现与当前数据库协议不同；不会自动迁移旧数据库，也不要直接把新版指向旧版数据库。
