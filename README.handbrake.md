# Cute Cat — HandBrake edition

A self-hosted web workbench that drives the **real HandBrakeCLI**. It is a
ground-up rewrite alongside the legacy Rust/FFmpeg service, which is left
untouched. Everything new lives under `next/` plus three new root files:

| New file | Purpose |
|---|---|
| `next/` | The service (pure Python stdlib) and native web UI |
| `Dockerfile.handbrake` | Image with the real engine |
| `compose.handbrake.yaml` | Compose deployment, incl. SMB/NFS examples |
| `config.example.handbrake.toml` | Example configuration |
| `.env.handbrake.example` | Compose environment template |
| `README.handbrake.md` | This document |

The legacy `Dockerfile`, `compose.yaml`, `src/`, `web/`, `migrations/` and
`README.md` are **not** modified by this work.

## Quick start (WSL Ubuntu)

All commands run in WSL, per project convention.

```bash
cd /mnt/c/Users/xiaohua/Documents/code/cute-cat

# 1. Install the engine (Debian/Ubuntu). Distribution builds may lack
#    hardware encoders — see "Building a hardware-enabled engine".
sudo apt-get install -y handbrake-cli

# 2. Run the test suite (no engine needed; uses the mock).
bash next/preview.sh        # or run the service directly, below

# 3. Start the service.
export PYTHONPATH="$PWD/next"
python3 -m cutecat --config config.example.handbrake.toml
```

Open <http://127.0.0.1:8080>.

There is also a preview launcher that uses a real engine when present and falls
back to the mock otherwise (clearly announced in the log):

```bash
bash next/preview.sh     # http://127.0.0.1:18084
```

### Running the tests

```bash
cd next
export PYTHONPATH="$PWD:$PWD/tests"
for f in tests/test_*.py; do python3 "$f"; done
# or:
python3 -m unittest discover -s tests -t tests
```

Expected: **98 tests, all passing.** Tests use the interface mock and never
require a real engine, GPU or media file.

### Checking engine availability

```bash
PYTHONPATH=next python3 -m cutecat --check
```

Prints the resolved binary, version, and hardware encoders, and exits non-zero
when no engine is found.

## Architecture

```
next/
  cutecat/
    config.py     TOML config + environment overrides
    pathsafe.py   storage-root containment (also guards preset path fields)
    engine.py     HandBrakeCLI wrapper: probe, scan, presets, encode, progress
    spec.py       structured spec -> whitelisted argv
    presets.py    official list + JSON import with path-field validation
    store.py      SQLite: jobs, logs, presets, settings
    worker.py     persistent queue, cancellation, logging
    server.py     HTTP API + static assets (stdlib http.server)
    cli.py        entrypoint
  web/            index.html, styles.css, app.js (no build step)
  tools/          mock_handbrakecli.py (tests only)
  tests/          98 tests
```

### How a job runs

1. The browser posts a **structured spec** (never raw CLI flags) to
   `POST /api/v1/jobs`, with a storage-root id and a *relative* path.
2. The server validates paths (`realpath` containment), validates the spec
   against the whitelist, translates it to argv, and stores the job.
3. The worker claims the job atomically from SQLite, re-validates the paths,
   runs `--scan --json`, then runs the encode with `--json`.
4. `--json` progress lines on stderr update the job row; every line is logged.
5. Cancellation signals the process group; partial output is removed.

### Engine CLI surface used

```
HandBrakeCLI --version
HandBrakeCLI --help
HandBrakeCLI --preset-list
HandBrakeCLI --preset-import-file <file>
HandBrakeCLI -i <in> --scan --json
HandBrakeCLI -i <in> -o <out> [whitelisted flags] --json
HandBrakeCLI -i <probe clip> -o <tmp> -f av_mkv -e <encoder> --previews 1:0
```

The last one exists only to answer "does this build contain that encoder?" — see
[How "is this encoder installed?" is actually decided](#how-is-this-encoder-installed-actually-decided).

## Configuration

See `config.example.handbrake.toml`. Key points:

* `engine.handbrake_bin` — path or name of the real CLI.
* `[[storage_roots]]` — the only directories the service may touch. Clients
  submit a root id plus a **relative** path; absolute paths, `..`, drive
  letters, NUL bytes and symlink escapes are all rejected.
* `mount_marker` — optional file proving a network share is mounted, so an
  unmounted share is shown as unavailable instead of being treated as an empty
  local directory.
* `security.api_token` — leave empty for loopback; **set `CUTE_CAT_API_TOKEN`
  in the environment** for anything else. Secrets never go in the image.

Environment overrides: `CUTE_CAT_CONFIG`, `CUTE_CAT_LISTEN`,
`CUTE_CAT_DATABASE`, `CUTE_CAT_ENGINE`, `CUTE_CAT_API_TOKEN`.

The SQLite database must live on local storage — never on SMB/NFS.

## Docker

```bash
cd /mnt/c/Users/xiaohua/Documents/code/cute-cat
cp .env.handbrake.example .env      # fill in; keep out of version control
docker compose -f compose.handbrake.yaml up --build
```

The image:

* installs the **real** `handbrake-cli` package (apt-verified);
* runs as a **non-root** user (uid/gid 10001);
* uses a **read-only root filesystem**, `no-new-privileges`, and drops **all**
  capabilities;
* has **no** privileged mode, **no** Docker socket, **no** host mounts it
  performs itself;
* persists state in the `cute-cat-data` local volume.

> **Not verified:** no container runtime was available in the build
> environment, so this image has not been built or run here. Treat the build as
> untested until you run it.

### SMB / NFS

Network shares are mounted **before** the container starts, by Docker or the
host — never by the application. `compose.handbrake.yaml` contains commented
examples for both, using Docker `local` volumes:

* **NFS** — `driver_opts: {type: nfs, o: "addr=…,rw,nfsvers=4", device: ":…"}`
* **SMB/CIFS** — `driver_opts: {type: cifs, o: "credentials=…,vers=3.0,uid=10001,…", device: "//host/share"}`

Use a **credentials file** (mode 600, never committed) rather than inline
secrets, which would be visible via `docker inspect`. On a rootless/unprivileged
daemon these mounts may be unavailable — mount on the host and bind-mount the
path instead. Place the `mount_marker` file at the share root once.

## Hardware encoding and licensing

Hardware encoders are passed through **only when the engine really contains
them**. No usable GPU device is present here, so no hardware path has been
demonstrated to encode; the UI marks every GPU card *GPU 转码未实测*.
Encoder names follow HandBrake (`nvenc_h264`, `qsv_h265`, `vce_h264`,
`vt_h264`, …), deliberately **not** FFmpeg's `vaapi`/`amf` naming.

### How "is this encoder installed?" is actually decided

`HandBrakeCLI --help` **under-reports** the encoder table. Measured on 1.11.0:
it lists 16 video encoders while the build contains at least 23 — `nvenc_h265`,
`nvenc_h265_10bit` and every `qsv_*` are missing from `--help` but are
genuinely present. A catalog built from `--help` alone therefore told users to
install encoders they already had.

So presence is settled by **instantiation**, not by the help text. For each
candidate the engine runs one throwaway job against a generated one-frame
320×240 clip (`-f av_mkv -e <encoder> --previews 1:0`) and reads HandBrake's own
printed job configuration:

| Verdict | Meaning |
|---|---|
| `works` | The encoder instantiated and the tiny encode muxed a video track |
| `blocked` | The encoder instantiated, then the encode failed — the build has it, this machine cannot run it |
| `absent` | The encoder never reached the job configuration — the build really lacks it |

Two details matter and are easy to get wrong:

* The **exit code is not the success signal** — a successful `x265` encode exits
  `4` while a failed NVENC one exits `3`. Success is read from HandBrake's
  `mux: track 0` line.
* Only the `* video track` block counts. Every run also names an *audio*
  encoder, and reading the whole log would mark every encoder as present.

If the probe cannot confirm a control encoder that every build ships (`x264`),
the whole result is discarded rather than being read as "not installed". The
probe costs roughly 1–2 s in total (parallel, 4 workers) and is cached for
5 minutes; the UI's **重新检测** forces a real re-probe.

Cards carry one of three verdicts: *引擎支持*, *缺少硬件支持* (in the build, no
usable hardware — nothing to install), or *当前引擎不含* (the build really lacks
it). Only the last one shows acquisition guidance.

### Acquiring an engine that contains an encoder

Encoders are **compiled into the HandBrake binary**; there is no
`install nvenc_h265`. Getting one means swapping the engine binary, which is a
host-level operation. The card shows the options and copyable commands, and
**Cute Cat never runs any of them** — the service has no package manager, no
Docker socket and no privilege, by design.

Distribution `handbrake-cli` packages are frequently built **without** hardware
encoders. If you need NVENC/QSV/VAAPI, build HandBrake from source with the
relevant flags and point `engine.handbrake_bin` at the result. The upstream
source could not be fetched in this environment (network policy blocked the
official hosts), so the guidance deliberately tells you to read the flag off
`./configure --help` for your release instead of naming one that may silently do
nothing — this remains an **open blocker**, not an oversight.

Licensing: HandBrake is GPL-2.0-or-later. HandBrake is a front end to
libav*/x264/x265, whose patent and licence obligations depend on your build
configuration and jurisdiction. Verify separately before redistributing an
image.

## API

```
GET  /health/live | /health/ready
GET  /api/v1/capabilities          engine + config + feature matrix + options
GET  /api/v1/config                public config (never the token)
GET  /api/v1/storage-roots
GET  /api/v1/storage-roots/<id>/entries?path=<rel>
GET  /api/v1/encoders[?refresh=1]  encoder catalog; refresh=1 forces a re-probe
GET  /api/v1/presets               official + imported + candidate files
POST /api/v1/presets/import        import a preset JSON from a root
POST /api/v1/probe                 scan a file
GET|POST /api/v1/jobs
GET  /api/v1/jobs/<id>
POST /api/v1/jobs/<id>/cancel
GET  /api/v1/jobs/<id>/logs
```

Auth: when `security.api_token` is set, every `/api/v1/*` call needs
`Authorization: Bearer <token>` or `X-API-Token: <token>`.

## Remaining blockers (accurate list)

1. **No container runtime** → `Dockerfile.handbrake` and
   `compose.handbrake.yaml` are unbuilt. Resolve with `docker compose build`.
2. **No usable GPU device** → no hardware encode has been run end to end. The
   probe reports what the build contains and what this machine can start, but
   "starts" is not "encodes your media"; verify on the target host.
3. **Upstream HandBrake source unobtainable** here (network policy) → no
   hardware-enabled build recipe; document the one you use.
4. **A real end-to-end encode is not part of the suite** → the encode path is
   exercised against the mock. Run one manual job against the real CLI on the
   target host before relying on it.
5. **Live preview/thumbnails not implemented** → disabled in the UI by design.
